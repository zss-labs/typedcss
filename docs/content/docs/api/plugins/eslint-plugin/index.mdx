`@typedcss/eslint-plugin` is the ESLint plugin for TypedCSS.

## Installation

```bash
pnpm add -D @typedcss/eslint-plugin
```

## Usage

```js
import typedcss from '@typedcss/eslint-plugin';

export default [typedcss.configs.recommended];
```

## Rules

`recommended` turns on every rule below. Each one is prefixed with `@typedcss/`.

| Rule | Level | Reports |
| :-- | :-- | :-- |
| `expand-border-shorthands` | warn | a border shorthand that bundles a width, a style and a color; fixable |
| `no-combinator` | error | `>`, `+`, `~` and the descendant combinator outside a functional pseudo-class |
| `no-destructure` | error | destructuring the TypedCSS API |
| `no-inline-object` | error | an inline object on the styling prop or in `css.props()` |
| `no-inner-call` | error | an API call inside a function |
| `no-invalid-selector` | error | a selector or nesting order the compiler cannot place |
| `no-mixed-styling-props` | error | the styling prop on an element that also has `className` or `style` |
| `no-mutable-binding` | warn | a `let` or `var` in a style definition |
| `no-order-dependent-overlap` | warn | two declarations in one style that only source order can rank |
| `no-unknown-css-properties` | error | a property CSS does not have |
| `no-unused-keys` | warn | a key nothing in the same component file reads |
| `no-unresolved-composition` | warn | a `css.props()` result turned into a string, combined with other class names or passed to another function |
| `sort-properties` | warn | properties out of the recommended order; fixable |
| `format-properties` | warn | a style written on one line, or with empty lines between its properties; fixable |
| `validate-values` | warn | a value the property does not accept |
| `validate-pseudos` | warn | a misspelled or malformed pseudo-class or pseudo-element |
| `validate-at-rules` | warn | an at-rule other than `@media`, `@container`, `@supports` and `@starting-style` |

Two more rules ship with the plugin and stay off until you ask for them. See
[Optional rules](/docs/api/plugins/eslint-plugin/optional-rules).

## Configuring the styling prop

`no-inline-object`, `no-mixed-styling-props` and `no-unresolved-composition`
need to know which JSX prop carries styles. It is `sx` unless you changed it, so
most projects configure nothing.

If you did rename it — via `styleProp` on `withTypedCSS` or on the unplugin
options — tell the plugin the same name. The lint the bundler plugins run in the
build is given that name already. ESLint cannot read it from your bundler
config, so set it once in `settings` and every rule picks it up:

```js
import typedcss from '@typedcss/eslint-plugin';

export default [
  typedcss.configs.recommended,
  {
    settings: {
      typedcss: { styleProp: 'sx' },
    },
  },
];
```

A single rule can override that if you need it to:

```js
{
  rules: {
    '@typedcss/no-mixed-styling-props': ['error', { styleProp: 'sx' }],
  },
}
```

The name must match whatever the loader or unplugin was given. If they disagree,
the lint rules report against a prop the compiler never transforms.

## Rule details

### expand-border-shorthands

Expands a border shorthand that bundles a width, a style and a color —
`border`, `borderBlock`, `borderInline`, and the eight edge forms — into the
three declarations it stands for. Those bundles are the only properties left
that cross an axis shorthand without either containing the other, so expanding
them turns the last unrankable pairs into ordinary shorthand-to-longhand ones.

Fixable. A value it cannot split, such as `var(--edge)` or `inherit`, is
reported without a fix: leaving it silent would let the expanded declarations
elsewhere outrank it.

```js
borderTop: '1px solid red'
// becomes
borderTopColor: 'red', borderTopStyle: 'solid', borderTopWidth: '1px'
```

A shorthand resets what it omits, so `borderBlock: 'solid'` expands with
`medium` and `currentcolor` written out.

### no-invalid-selector

Disallow invalid selector inside `css.create()` and `css.keyframes()` and `css.viewTransitionClass()`.  
`create()` example: (Pseudo -> Query, Query -> Query)  
Also reports a functional pseudo-class nested inside one of the same name, such as `:where(:where(.a), .b)`, and flattens it with a fix when the nested call is a whole argument. `:not()` may nest inside `:not()`. Reports a key nested deeper than 16 levels or holding a stray quote.

### no-order-dependent-overlap

Warns when two properties in one style overlap but neither outranks the other,
so the one written last wins. It covers one property under its logical and its
physical name, and two shorthands that cross without either containing the
other. A shorthand and its longhand are ranked by specificity and never
reported.

It also reports two conditions in one style where one provably matches a subset
of the other — `(min-width: 900px)` inside `(min-width: 600px)`, or two queries
naming the same container — and the narrower one is written first. The optimizer
places the narrower one last whatever the source says, so the declarations read
the wrong way round. The swap is offered as a suggestion rather than a fix.

A pair of spellings is one property in a horizontal writing mode and two
properties in a vertical one, which is per element and cannot be read from the
source. The rule reads them as one property; disable the line where an element
is known to be vertical.

## CLI (typedcss-lint)

This package provides a CLI command, `typedcss-lint`, as a convenient way
to run typedcss's custom ESLint rules.

It runs `oxlint`, which this package depends on, for fast linting with code
snippets in output, so oxlint needs no separate install.

The CLI comes with the plugin, so it needs no separate install:

```bash
typedcss-lint
```

The process exits with a non-zero status code if any errors or warnings are found,
making it suitable for use in CI and build pipelines.

### Styling prop

If the styling prop is renamed, pass the name with `--style-prop`. Without the
flag, `typedcss-lint` asks ESLint for `settings.typedcss.styleProp` when ESLint
and a flat config are installed, and uses `sx` otherwise:

```bash
typedcss-lint --style-prop sx
```

### Aborting Builds on Lint Errors (Parallel Pipeline)

You can run `typedcss-lint` in parallel with your build command (e.g. `next build` or `vite build`) using the `--` separator:

```json
{
  "scripts": {
    "build": "typedcss-lint -- next build"
  }
}
```

If `typedcss-lint` detects any styling errors or warnings, it will print the diagnostics, kill the build process immediately, and exit with a non-zero code. This avoids compiling when styling validation fails.

With `@typedcss/next-plugin` and `@typedcss/unplugin` (except on esbuild and Bun), this lint is integrated into the build by default, so it needs no setup. Pass `lint: false` to the plugin to build without it.
