[`examples/example-rspack`](https://github.com/zss-labs/plumeria/tree/main/examples/example-rspack) shows how to use [`@typedcss/unplugin`](https://www.npmjs.com/package/@plumeria/unplugin) in Rspack.  
The plugin compiles TypedCSS styles into CSS, with HMR in development.

`npx @typedcss/init` detects Rspack and writes this setup for you; see [@typedcss/init](/docs/api/migrate/init). The rest of this page is the same setup by hand.

## Installation
```sh title="Terminal"
pnpm i -D @typedcss/unplugin
```

## Usage
```ts title="rspack.config.js"
import { rspack } from '@rspack/core';
import { ReactRefreshRspackPlugin } from '@rspack/plugin-react-refresh';
import typedcss from '@typedcss/unplugin';

const isDev = process.env.NODE_ENV === 'development';

export default {
  entry: './src/index.tsx',
  output: {
    filename: 'bundle.js',
    clean: true,
  },
  resolve: {
    extensions: ['.ts', '.tsx', '.js'],
  },
  module: {
    rules: [
      {
        test: /\.tsx?$/,
        use: {
          loader: 'builtin:swc-loader',
          options: {
            jsc: {
              parser: { syntax: 'typescript', tsx: true },
              transform: {
                react: {
                  runtime: 'automatic',
                  development: isDev,
                  refresh: isDev,
                },
              },
            },
          },
        },
      },
    ],
  },
  plugins: [
    typedcss.rspack(),
    new rspack.HtmlRspackPlugin({ template: './src/index.html' }),
    isDev && new ReactRefreshRspackPlugin(),
  ].filter(Boolean),
  devServer: {
    hot: true,
    port: 3000,
  },
};
```

## typedcss.d.ts

`@typedcss/css` ships no prop declaration of its own, so name the styling prop your project compiles with.

For the default name (`sx`), reference the declaration that ships with the package, in `src/` when the project has one or at the application root otherwise:

```ts title="typedcss.d.ts"
/// <reference types="@typedcss/css/sx" />
```

If you set a custom `styleProp` (such as `'classStyle'`), declare that name instead, and keep it the same as the one passed to the plugin; see [Declaring the styling prop](/docs/api/types/Style#declaring-the-styling-prop).
