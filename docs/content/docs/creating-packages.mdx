---
title: 'Creating Packages'
description: 'Ship the source to compile with the app, or a dist that needs no setup.'
---

A component library built with TypedCSS ships one of two ways.

|                                  | Source                          | Dist                    |
| -------------------------------- | ------------------------------- | ----------------------- |
| What you publish                 | `src`                           | `dist` and a stylesheet |
| The app needs the bundler plugin | Yes                             | No                      |
| The app overrides with `sx` | Yes                             | No                      |
| Style work at runtime            | `css.props` merge               | `css.props` merge       |

Ship the source when the people installing it build with TypedCSS. Ship a dist when
they might not.

## Ship the source

The package points a `typedcss` export condition at its TypeScript source, as
[tokens do](https://plumeria.dev/docs/thinking-in-plumeria#across-packages), and the app's build compiles
its components along with the app's own files.

```json title="package.json"
{
  "name": "ui-kit",
  "type": "module",
  "files": ["src"],
  "exports": {
    ".": { "typedcss": "./src/index.ts", "types": "./src/index.ts" },
    "./*": { "typedcss": "./src/*.tsx", "types": "./src/*.tsx" }
  },
  "peerDependencies": {
    "@typedcss/css": "*",
    "react": ">=18"
  }
}
```

A component takes a style through a prop and applies it last, so the caller wins:

```tsx title="src/Button.tsx"
import * as css from '@typedcss/css';

const styles = css.create({
  base: {
    paddingBlock: 8,
    paddingInline: 16,
    color: 'white',
    backgroundColor: 'gray',
    borderRadius: 6,
  },
});

export const Button = ({
  children,
  sx,
}: {
  children: React.ReactNode;
  sx?: css.Style;
}) => <button sx={[styles.base, sx]}>{children}</button>;
```

The app lists the package in its dependencies and passes its own styles:

```tsx title="app.tsx"
import * as css from '@typedcss/css';
import { Button } from 'ui-kit';

const styles = css.create({
  primary: { backgroundColor: 'royalblue' },
  danger: { backgroundColor: 'crimson' },
});

export const App = () => (
  <>
    <Button>Default</Button>
    <Button sx={styles.primary}>Primary</Button>
    <Button sx={styles.danger}>Danger</Button>
  </>
);
```

The app's build compiles `Button` with every style the app hands it:

```js title="dist/assets/index.js"
var Button = ({ children, sx }) =>
  jsx('button', {
    className:
      'xnuwkl3w xgxw0ba0 xf882boo x1b4ohri ' +
      ({ x9ct19gt: 'xbpntsfg', x409xipj: 'x5iwg3of' }[sx] ||
        'xc4k1q4z'),
    children,
  });
```

The override is a lookup the compiler wrote, not a merge. Crossing the package
boundary leaves nothing to resolve while your users render, and editing an override
in the app updates the component in development.

The bundler plugin needs no extra setup. It resolves the package to its source,
keeps it out of dependency pre-bundling in Vite, and adds it to `transpilePackages`
in Next.js. Every file in the directories the exports point to is compiled, so keep
only what ships there, and tests and stories outside them.

> **Keep the overrides within reach**
>
> A received style can be applied on an element the component renders, or passed on
> to another component; the merge waits until the element.
>
> A `default` condition pointing at a dist is allowed for apps without TypedCSS, but
> those apps get the dist and its overrides are not applied.

## Ship a dist

The library compiles itself. The class names sit in the JavaScript and the rules in
a stylesheet, so the people installing it need no bundler plugin and no dependency
on TypedCSS. An `sx` from the app is not read.

```js title="build.js"
import esbuild from 'esbuild';
import fs from 'node:fs';
import typedcss from '@typedcss/unplugin';

await esbuild.build({
  entryPoints: ['src/index.tsx'],
  bundle: true,
  outfile: 'dist/index.js',
  external: ['react', 'react/jsx-runtime'],
  plugins: [typedcss.esbuild({ include: /\.[jt]sx?$/ })],
  loader: { '.tsx': 'tsx', '.ts': 'ts' },
  format: 'esm',
  jsx: 'automatic',
});

fs.writeFileSync(
  'dist/index.js',
  `import './index.css';\n${fs.readFileSync('dist/index.js', 'utf-8')}`,
);
```

The last line points the JavaScript back at its stylesheet. esbuild, Bun, Rollup
and Rolldown leave the extracted stylesheet unattached, and a library has no HTML to
link it, so your users inherit it by importing the component.

```json title="package.json"
{
  "name": "your-lib",
  "type": "module",
  "files": ["dist"],
  "exports": {
    ".": "./dist/index.js"
  },
  "peerDependencies": {
    "react": ">=18"
  },
  "devDependencies": {
    "@typedcss/css": "latest",
    "@typedcss/unplugin": "latest"
  }
}
```
